## Codebase Patterns
- Read docs/SYSTEM_DESIGN.md before every story. It is the source of truth.
- Python 3 standard library only (tomllib, json, unittest, xml.etree, urllib). No pip installs; pytest is NOT available.
- Run tests: python3 -m unittest discover -s tests -v
- Package name is `etrace` (not `trace`, which shadows the stdlib module). Core module is etrace/container (the preference container); see docs/SYSTEM_DESIGN.md section 3. Root CLAUDE.md repeats the hard boundary.
- Config: etrace.config.load(path) -> frozen Config; ConfigError for every invalid input. Relative paths resolve against trace.toml's dir. tasks values are always lists (audit is 'Ddd HH:MM'). When adding a config key, update _TOP_KEYS/defaults AND examples/trace.toml (a test checks every key is documented).
- Storage: use etrace.store.Store(data_dir).append(name, record)/read_all(name) for every *.jsonl (name 'feedback' -> feedback.jsonl); records need a unique string 'id' per file. Whole JSON files (rules.json) go through Store.write_json / store.write_json_atomic. Never rewrite JSONL history; express edits as new records linking the old id.
- Tests must use tempfile dirs; never write outside the repo or touch the network.
- NEVER add real personal data, real emails, Notion IDs or absolute /Users/ paths. Example data is fictional.
- Bilingual: code/README in English; preset labels, prompts and templates have zh and en.
- Default PAD 27-word table (zh), rows = P,A level; columns = low D | mid D | high D:
  P低A低: 无助|沮丧|轻蔑   P低A中: 担忧|烦躁|不满   P低A高: 恐慌|紧张|愤怒
  P中A低: 茫然|平静|淡定   P中A中: 困惑|专注|笃定   P中A高: 震惊|惊讶|警觉
  P高A低: 依恋|满足|惬意   P高A中: 感动|开心|自豪   P高A高: 惊喜|兴奋|豪迈
- Journal notes: etrace.journal.load/parse -> Document; change AI text only via replace_ai_block(doc, name, text) (keeps the block's '## title' line) and write via journal.save(doc, path), which raises ProtectedBlockChanged if any user:*/verbatim block differs from the file on disk. Never write note files directly. Template hints are '<!-- hint: ... -->' comments; strip them with journal.strip_hints before ingesting user text.
- Verbatim block is append-only: write it only via journal.append_verbatim(doc, text, written_on, happened_on, language). First fill has no header; later additions get a '补写于 …｜实际发生于 …' header. Never assign verbatim Block.body directly; save() only accepts the exact hash produced by append_verbatim on top of the on-disk body.
- Rules: etrace.container.rules.add_rule(data_dir, rule_id, scope, text, expressed_at, source_feedback_id=None, reason=None); active_rules(data_dir, scope=None); history(data_dir, rule_id); get(); version(). data_dir may be a path or Store. expressed_at must be a timezone-aware ISO datetime. Store.lock() is NOT reentrant: for read-modify-write use `with store.lock():` + store.write_json_atomic, not Store.write_json.
- Feedback: etrace.container.feedback.ingest_notes(journal_dir, data_dir, now=None) -> IngestResult(added, unchanged, errors, ok). Entry id = 'DATE:feedback:sha12'. feedback.current(data_dir, note_date=None) gives latest versions (records not referenced by a later 'supersedes'). Use feedback ids from these records as source_feedback_id / answered feedback_id.
- Questions: etrace.container.questions.add_question(data_dir, source, date, evidence={'kind': 'quote'|'behavior', 'text'}, candidates=[a, b], uncertainty, dimensions=[...], dedupe_key, now=None) -> id 'Q-YYYYMMDD-N'. follow_up/answer(feedback_id must exist in feedback.jsonl)/skip append event records; get/all_questions/open_questions replay them. daily_status(data_dir, date, scan_ok) -> list or questions.NO_QUESTIONS / SCAN_FAILED.
- Check-then-append on a JSONL file: `with store.lock():` read_all + validate + store.append_locked(name, record) (Store.append would deadlock on the non-reentrant lock).
- Decisions/usage: decisions.decide(data_dir, feedback_ids, decision_text, value_source='user'|'agent_decision', rule_changes=[{rule_id, scope, text, expressed_at, source_feedback_id?, reason?}], now) -> 'D-YYYYMMDD-N'; decisions.mark_pending(id, reason). usage.record(data_dir, task, target, rule_version, feedback_ids, decision_ids, before, after, status, verified_readback=True, now) -> 'U-YYYYMMDD-N'. Only usage.applied() (a verified changed/confirmed receipt) means a decision was used; validate.validate(data_dir, now).ok checks the chain.
- Note outreach: etrace.outreach.note.write(journal_dir, data_dir, date, scan_ok, language, preset, decision_ids=None, summary=None, now) rewrites ai:questions (creates the note if missing), reads back, then appends notifications.jsonl ('N-YYYYMMDD-N', channel/status/verified_readback/question_ids/decision_ids/daily_status/content_hash). Default decisions = those not reported on an earlier day. Wrap user-facing text with note._wrap (zh 40 / en 72 chars) to stay phone-readable.

## Hard boundary
- NEVER read from or write to ~/protected-dir-1, ~/protected-dir-2, or any Notion workspace while building this project. Work only inside this repository.
- v1 reads only the user's own journal notes. Do NOT build readers for ChatGPT / Claude / Google AI Mode conversation logs.

## 2026-10-07 - US-002
- Implemented etrace/store.py: Store(data_dir, lock_timeout, stale_after) with append/read_all/write_json/lock, module-level write_json_atomic (mkstemp in same dir + fsync + os.replace, temp removed on failure).

- Files: etrace/store.py, tests/test_store.py

  - Duplicate check reads the whole file per append: fine for v1 sizes.
  - JSONL lines are written with ensure_ascii=False so Chinese stays readable.

## 2026-10-07 - US-024
- Replaced fill_verbatim with journal.append_verbatim(doc, text, written_on=None, happened_on=None, language="zh"). Empty block: text appended with no header. Filled block: appends '\n补写于 W｜实际发生于 H\n\ntext\n' (en: 'Added on W | happened on H'); keeps exactly one blank line before the addition and never touches existing bytes (even a body without a trailing newline).
- Dedupe: verbatim content is split into sections by header lines; same text hash for the same happened_on, or equal to the original (headerless) section, is a no-op.
- save() allows a verbatim change only when (disk hash, new hash) equals doc._verbatim_append = (hash before the first append, hash after the last append), so several appends per session work and any other edit (changed/removed/reordered bytes, edits on disk after load) raises ProtectedBlockChanged.
- Files: etrace/journal.py, tests/test_journal.py
- **Learnings for future iterations:**
  - written_on/happened_on are required only once the block is filled; dates go through journal._iso (date or 'YYYY-MM-DD').
  - fill_verbatim is gone; callers ingesting a day's original text should call append_verbatim and rely on its dedupe for reruns.

  - No retire/remove API yet; if decisions need to drop a rule without replacement, add it in rules.py with a version bump.
