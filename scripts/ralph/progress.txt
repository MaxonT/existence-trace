## Codebase Patterns
- Read docs/SYSTEM_DESIGN.md before every story. It is the source of truth.
- Python 3 standard library only (tomllib, json, unittest, xml.etree, urllib). No pip installs; pytest is NOT available.
- Run tests: python3 -m unittest discover -s tests -v
- Package name is `etrace` (not `trace`, which shadows the stdlib module). Core module is etrace/container (the preference container); see docs/SYSTEM_DESIGN.md section 3. Root CLAUDE.md repeats the hard boundary.
- Config: etrace.config.load(path) -> frozen Config; ConfigError for every invalid input. Relative paths resolve against trace.toml's dir. tasks values are always lists (audit is 'Ddd HH:MM'). When adding a config key, update _TOP_KEYS/defaults AND examples/trace.toml (a test checks every key is documented).
- Storage: use etrace.store.Store(data_dir).append(name, record)/read_all(name) for every *.jsonl (name 'feedback' -> feedback.jsonl); records need a unique string 'id' per file. Whole JSON files (rules.json) go through Store.write_json / store.write_json_atomic. Never rewrite JSONL history; express edits as new records linking the old id.
- Tests must use tempfile dirs; never write outside the repo or touch the network.
- NEVER add real personal data, real emails, Notion IDs or absolute /Users/ paths. Example data is fictional.
- Bilingual: code/README in English; preset labels, prompts and templates have zh and en.
- Default PAD 27-word table (zh), rows = P,A level; columns = low D | mid D | high D:
  P低A低: 无助|沮丧|轻蔑   P低A中: 担忧|烦躁|不满   P低A高: 恐慌|紧张|愤怒
  P中A低: 茫然|平静|淡定   P中A中: 困惑|专注|笃定   P中A高: 震惊|惊讶|警觉
  P高A低: 依恋|满足|惬意   P高A中: 感动|开心|自豪   P高A高: 惊喜|兴奋|豪迈
- Journal notes: etrace.journal.load/parse -> Document; change AI text only via replace_ai_block(doc, name, text) (keeps the block's '## title' line) and write via journal.save(doc, path), which raises ProtectedBlockChanged if any user:*/verbatim block differs from the file on disk. Never write note files directly. Template hints are '<!-- hint: ... -->' comments; strip them with journal.strip_hints before ingesting user text.
- Verbatim block is append-only: write it only via journal.append_verbatim(doc, text, written_on, happened_on, language). First fill has no header; later additions get a '补写于 …｜实际发生于 …' header. Never assign verbatim Block.body directly; save() only accepts the exact hash produced by append_verbatim on top of the on-disk body.
- Rules: etrace.container.rules.add_rule(data_dir, rule_id, scope, text, expressed_at, source_feedback_id=None, reason=None); active_rules(data_dir, scope=None); history(data_dir, rule_id); get(); version(). data_dir may be a path or Store. expressed_at must be a timezone-aware ISO datetime. Store.lock() is NOT reentrant: for read-modify-write use `with store.lock():` + store.write_json_atomic, not Store.write_json.
- Feedback: etrace.container.feedback.ingest_notes(journal_dir, data_dir, now=None) -> IngestResult(added, unchanged, errors, ok). Entry id = 'DATE:feedback:sha12'. feedback.current(data_dir, note_date=None) gives latest versions (records not referenced by a later 'supersedes'). Use feedback ids from these records as source_feedback_id / answered feedback_id.
- Questions: etrace.container.questions.add_question(data_dir, source, date, evidence={'kind': 'quote'|'behavior', 'text'}, candidates=[a, b], uncertainty, dimensions=[...], dedupe_key, now=None) -> id 'Q-YYYYMMDD-N'. follow_up/answer(feedback_id must exist in feedback.jsonl)/skip append event records; get/all_questions/open_questions replay them. daily_status(data_dir, date, scan_ok) -> list or questions.NO_QUESTIONS / SCAN_FAILED.
- Check-then-append on a JSONL file: `with store.lock():` read_all + validate + store.append_locked(name, record) (Store.append would deadlock on the non-reentrant lock).
- Decisions/usage: decisions.decide(data_dir, feedback_ids, decision_text, value_source='user'|'agent_decision', rule_changes=[{rule_id, scope, text, expressed_at, source_feedback_id?, reason?}], now) -> 'D-YYYYMMDD-N'; decisions.mark_pending(id, reason). usage.record(data_dir, task, target, rule_version, feedback_ids, decision_ids, before, after, status, verified_readback=True, now) -> 'U-YYYYMMDD-N'. Only usage.applied() (a verified changed/confirmed receipt) means a decision was used; validate.validate(data_dir, now).ok checks the chain.
- Presets: etrace.presets.load(name, presets_dir=None) -> {'name','pad','g','xp','rules','question_templates'}, validated (ValueError 'NAME/file.json.field: msg'). Labels are {'zh','en'} objects; pick with presets.label(obj, language). Helpers: g_items(p) -> [(code, weight, label)], band(level) 1-5 -> low/mid/high, pad_word(p, P, A, D, language). Preset rules.json = {version, rules:[{id, scope, text:{zh,en}}]}: pass presets.label(rule['text'], lang) to rules.add_rule (it needs a str). xp.json dims ids are the same in both presets (rhythm, learning, boundaries, action, reflection, connection); only labels differ.
- Note outreach: etrace.outreach.note.write(journal_dir, data_dir, date, scan_ok, language, preset, decision_ids=None, summary=None, now) rewrites ai:questions (creates the note if missing), reads back, then appends notifications.jsonl ('N-YYYYMMDD-N', channel/status/verified_readback/question_ids/decision_ids/daily_status/content_hash). Default decisions = those not reported on an earlier day. Wrap user-facing text with note._wrap (zh 40 / en 72 chars) to stay phone-readable.
- PAD: etrace.models.pad.PadPoint.from_dict(agent_json) (PadError.errors = ['field: msg'] for CLI exit 2); slot is a SLOTS name or 'HH:MM' (pad.slot_of maps times to slots; SLOT_HOURS gives fixed chart positions for slot-only points). project(p,a,d,preset=None,language) -> 27-table word (values <1 count as level 1). daily_summary(points) -> DailySummary(.P/.A/.D, unknown_durations, equal_weighted). validate_day(points).ok/.problems.
- G: etrace.models.g.compute(items, preset=None) -> GResult(B, E, G, items{code: GItem}, .missing); items are GItem or dicts (GItem.from_dict, GError.errors = ['items[i].field: msg']). Values unrounded; use g.display(v, lang) ('6.3', None -> 缺/n/a) for people. g.legend(preset, lang) is the symbol explanation.
- G gap fill: g.gap_fill(date, real_items, history{date: items}) -> GDay(items all 8, explicit_gap_fill, .filled); filled GItems have provenance 'gap_fill', confidence low, method, neighbors [{date,value}]. Persisted day revisions live in g.jsonl via g.record(data_dir, date, items, now) / g.refill / g.latest / g.revisions (id 'G-YYYYMMDD-rN', supersedes). g.training_eligible(day) must gate every training/calibration use.
- G predictions/calibration: g.predict(data_dir, date, preset, now) freezes g.latest into predictions.jsonl ('P-YYYYMMDD-N', dedupes same date+revision+rubric_version); g.feedback(data_dir, prediction_id, targets={code: number}, text, expressed_at, now) -> g_feedback.jsonl ('GF-YYYYMMDD-N'), rejected unless prediction created_at < expressed_at. g.calibration(data_dir, preset|version) -> Calibration(.enabled, .reason, .bias, .apply(code, value)); always call .apply, it is a no-op when disabled.
- XP: etrace.models.xp.score_day(date, levels{dim_id: int 0-4, all six required}, ordinary, events=[{event_id, occurred_on (== date), points>=0, title?}], preset) -> XPDay(.total int half-up, .raw_total); xp.record(data_dir, day, now) -> xp.jsonl 'XP-YYYYMMDD-rN' (rejects event_id booked on another day); xp.week_total(days|data_dir, monday) -> WeekTotal(total, days, missing).
- Chart: etrace.chart.pad_svg(points, kind='day'|'week', language, preset=None) -> SVG string (data lines are the only <path> elements, class 'pad-line'; grid uses <line>). chart.smooth/local_linear are reusable for the G chart (US-013).
- Email: etrace.outreach.email.load_credentials(path) -> Credentials (repr/errors never show the password; reasons go through _reason to scrub it). send(data_dir, creds, date, scan_ok, language, kind='questions'|'report'|'audit', now) -> SendResult; notifications.jsonl records have channel 'email' + kind; 'sent' only after IMAP finds the Message-ID in sent_folder. read_replies(data_dir, creds, now) -> ReplyResult, feedback records with source 'email', id 'email:MSGHASH12:QID|general'. Tests patch mail.smtplib.SMTP_SSL/SMTP and mail.imaplib.IMAP4_SSL with in-memory fakes (tests/test_outreach_email.py).
- Audit: etrace.container.audit.weekly(data_dir, as_of, audits_dir, now=None, language) -> report dict (passed, chains[{kind, root, problems, open}], decisions_without_receipt, receipts_without_readback, samples{applied, not_applicable}, reactions{approved, objected, replied, silence}); writes audits_dir/YYYY-Www.{json,md}. Users reply to a decision by naming its D-id in feedback.
- Checkpoint: etrace.checkpoint.checkpoint(root_dir, message, remote=None) -> CheckpointResult(committed, commit, initialized, pushed, push_error). root_dir is the user data root (holds journal/, data/, audits/), not Store's data/ dir. Pass cfg.git_remote as remote; None never pushes. Raises CheckpointError if git is missing or a local step fails; push failures only set push_error. Git tests patch GIT_CONFIG_GLOBAL/GIT_CONFIG_NOSYSTEM/HOME and skipUnless(shutil.which('git')).
- CLI: etrace/cli.py main(argv) -> exit code; every command prints one JSON object on stdout, errors go to stderr as 'error: field: msg'. Exit 0 ok, 1 ran-but-failed (validate problems, email not sent, push error; raise cli.Failure(msg, result)), 2 bad input (raise cli.InputError(list) or a module error listed in cli._INPUT_ERRORS). Config lookup: --config, $ETRACE_CONFIG, ./trace.toml, ~/existence-trace-data/trace.toml. Data root layout: ROOT/{trace.toml, journal, data, audits, charts, presets/NAME}; cli.load_preset prefers ROOT/presets copy. New subcommands: add a cmd_* function + parser entry in build_parser (FILE commands use read_json + check_fields).
- PAD persistence: pad.record(data_dir, points, now) -> pad.jsonl 'PAD-YYYYMMDD-N' (unchanged points skipped, same date+slot supersedes); pad.points_for(data_dir, date) -> current PadPoints in time order.
- Prompts: etrace.prompts.render(task, cfg, data_dir, language=None) -> text < 6000 chars; templates are etrace/prompts/{zh,en}/TASK.md (string.Template: $name, $$ literal; $principles inlines _principles.md, $rules lists active rules and truncates with a `rules list` pointer). Never put cfg.data_dir or any path into a prompt. CLI: `prompt TASK [--language] [--raw]` (--raw returns cli.RawText, printed as plain text, for scheduler scripts). When a CLI command or JSON shape changes, update both languages' prompt files (tests/test_prompts.py checks each task names its commands).
- Scheduler: etrace.adapters.scheduler.render(target, cfg) -> {relpath: text}; write(target, cfg, out_dir) only writes files (never installs). Generated runs render prompts at run time via env_command(cfg) (cd ROOT && export ETRACE_CONFIG/PYTHONPATH, so the spawned agent inherits them) + `python3 -m etrace prompt TASK --raw`. CLI: `schedule --target codex|claude-code|cron --out DIR`.
- feedback.jsonl holds both note (source 'note') and email (source 'email') records; note intake only treats source 'note' records as editable/vanishable.
- Notion: etrace.adapters.notion.load_credentials(cfg.credentials['notion']) (TOML token + parent_page_id) and push(data_dir, creds, journal_dir, date, now, transport=None) -> PushResult; notion.jsonl 'NO-YYYYMMDD-N' (pushed only after the child-block count reads back; unchanged note = no push; changed note = new page, then archive the old one). HTTP goes through transport(method, url, headers, body) -> dict; tests pass a fake (tests/test_notion.py FakeNotion) or patch notion.urllib_transport. Notion is write-only: never read page content back into notes. CLI: `notion push [--date]`.
- Privacy: tests/test_privacy.py scans git tracked + untracked (non-ignored) files, except docs/SYSTEM_DESIGN.md, for emails (only example.com/.org/.net allowed), 32-hex or UUID ids and '/Users/<name>' paths. In tests, build fake real-looking values by string concatenation so the scan does not flag the test itself.
- Example persona: examples/persona/{journal,agent,expected.json}; tests/test_example.py runs the full CLI loop on it. If a CLI command, JSON shape, note template or score formula changes, regenerate/adjust these files and expected.json (feedback ids are DATE:feedback:sha12 of the entry text, so editing feedback text changes them).
