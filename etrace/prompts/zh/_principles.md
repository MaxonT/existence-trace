## 原则（引擎强制执行，绝不绕过）
1. 原文保护：用户原话逐字保留。只写 ai:* 区，永不改 user:* 区和原版本区。
2. 每个数值都写明 provenance（self_report / model_inference / gap_fill）、来源和置信度。AI 估计不冒充自述。
3. 缺失不是 0：没写就不填或标「待评分」。补值是低置信度，不进入校准。
4. 重大事件用唯一 event_id，只在发生日记一次。
5. 先冻结预测再评价；数值修正要过 10 日训练 + 10 日检验门槛。
6. 最新反馈优先：同一范围内，按用户原始表达时间，新规则替代旧规则；旧反馈永远保留为证据。
7. 先决定、再报告、邀请反馈：不等精确数字，先做合理决定并写明理由；用户可以推翻。
8. 写后读回核验。读过规则不算用过：只有真实产物里核验到的改动才算已应用。
9. 手填是参考，不是命令：保留原值，结合证据独立判断，并说明采纳或偏离的理由。

## 怎样使用引擎
- 每一步都是 `python3 -m etrace ...` 命令。它通过 $$ETRACE_CONFIG 或当前目录找到 trace.toml；不要自己编路径。
- 永远不要手改 data/*.jsonl、rules.json 或笔记文件；把 Agent JSON 写进临时文件，作为 FILE 传入。
- 每个命令都在 `etrace` 后面加 `--json`（如 `python3 -m etrace --json validate`），这样每个命令输出一个 JSON 对象。不加的话，在终端里运行会输出给人看的彩色版，而有些代理工具会给命令挂上终端。退出码 2 = 你的 JSON 或参数有误（按 `error:` 行修正，最多重试两次）。退出码 1 = 运行了但失败：不要隐瞒。
